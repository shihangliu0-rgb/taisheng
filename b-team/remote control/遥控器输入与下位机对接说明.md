# 遥控链路交接文档

## 1. 交接目标

遥控器通过 LoRa 同时服务两块主控。遥控器把两块主控的数据合并为一个固定 10 字节帧；接收端按帧头解析后，第一主控使用前 6 字节，第二主控使用后 2 字节。

第二主控的队友只需要完成三件事：

1. 将接收串口配置为 `115200 baud、8N1`。
2. 从固定帧中取出并解析第二主控的 2 字节数据。
3. 对右侧六个按键和五个开关实现业务逻辑，并增加通信超时保护。

## 2. 当前链路

```text
遥控器 STM32F4
  USART6，115200 baud
          |
          v
      LoRa 透明传输
          |
          v
遥控接收 STM32F103
  USART3，115200 baud
          |
          v
  解析固定 10 字节遥控帧，并双向转发下游数据
  USART2，115200 baud
          |
          v
  第一主控使用固定帧中的前 6 字节，第二主控使用后 2 字节
          ^
          |
  第二主控回传数据经第一主控、接收板原样送回 LoRa
```

遥控器每 `50 ms` 发送一个固定 10 字节帧，因此两块主控的状态更新率均约为 `20 Hz`。一帧包含帧头 `A5 5A`、第一主控 6 字节和第二主控 2 字节。

发送端和接收端都不会在上电时自动读取或写入 E32 参数；两端模块必须预先配置为相同信道、空中速率和其它无线参数。应用串口固定为 `115200、8N1`，M0/M1 上电后保持低电平进入透明传输模式。

当前相关代码：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 遥控输入 | `user/RemoteInput.c` | ADC 采样、数字输入消抖、蜂鸣器 |
| 遥控发送 | `user/Remote.c` | 组装固定 10 字节帧并通过 USART6 发送 |
| 第一主控链路 | `../user/com_link/lora_link.c` | 使用固定帧中的前 6 字节，并按需转发第二主控数据 |
| LoRa 接收与转发 | `../遥控接收/Core/Src/remote_link.c` | 解析固定 10 字节帧、更新开关并双向转发 |

## 3. 输入归属

| 输入 | 硬件引脚 | 使用方 |
| --- | --- | --- |
| 左侧六键 | `PA0、PC1、PC0、PA1、PA2、PA4` | 本机主控 |
| 左、右摇杆 | `PB0、PB1、PC2、PC3` | 本机主控 |
| 左、右肩键 | `PA6、PA7` | 本机主控 |
| 本机拨动开关 | `PE0` | 本机主控 |
| 右侧六键 | `PD13、PD12、PD11、PD8、PD9、PD10` | 第二主控 |
| 第二主控开关 | `PE4、PE3、PE1、PD6、PD5` | 第二主控 |

数字输入在协议中已经统一为：`0` 表示松开或断开，`1` 表示按下或闭合。接收方不需要关心 GPIO 的低电平有效关系。

## 4. 数据格式

```text
帧头 `A5 5A` | 第一主控 6 字节 | 第二主控 2 字节
```

协议没有 ID、类型、长度、序号和 CRC。接收端通过 `A5 5A` 帧头和固定长度 10 字节完成同步；帧内不存在第一主控/第二主控轮换发送。

## 5. 第二主控接收内容

接收板 USART2 输出的是完整固定帧。第二主控只取帧内的第 8、9 字节（从 0 开始计数），即第二主控的 2 字节数据：

```text
key_bits switch_bits
```

### `key_bits`

| 位 | 遥控引脚 | 状态 |
| --- | --- | --- |
| bit0 | `PD13` | 1 为按下 |
| bit1 | `PD12` | 1 为按下 |
| bit2 | `PD11` | 1 为按下 |
| bit3 | `PD8` | 1 为按下 |
| bit4 | `PD9` | 1 为按下 |
| bit5 | `PD10` | 1 为按下 |
| bit6..7 | 保留 | 忽略 |

### `switch_bits`

| 位 | 遥控引脚 | 状态 |
| --- | --- | --- |
| bit0 | `PE4` | 1 为闭合 |
| bit1 | `PE3` | 1 为闭合 |
| bit2 | `PE1` | 1 为闭合 |
| bit3 | 保留，固定为 `0` | 忽略 |
| bit4 | `PD6` | 1 为闭合 |
| bit5 | `PD5` | 1 为闭合 |
| bit6..7 | 保留 | 忽略 |

空闲状态的完整测试数据为：

```text
00 00
```

可先用此帧检查第二主控解析器。

## 6. 第二主控解析要求

串口是连续字节流，不能假设一次 DMA 或中断正好收到一组数据。接收程序先寻找 `A5 5A`，再连续接收完整 10 字节，最后取第 8、9 字节更新按键和开关。建议连续 `200 ms` 没有完整帧时清除输入并停止对应机构。

当前固定帧没有序号、CRC、应答和重传。遥控输入是周期状态量，后续完整帧会覆盖旧状态；如需确认每帧必达，需要另行增加可靠传输协议。

## 7. 第一主控解析要求

第一主控从固定 10 字节帧中解析第 2 至第 7 字节（去掉帧头后为前 6 字节）。帧头用于同步，不再依赖发送间隔判断 6 字节或 2 字节分段。

| 字节 | 内容 |
| --- | --- |
| 0 | 左摇杆 X |
| 1 | 左摇杆 Y |
| 2 | 右摇杆 X |
| 3 | 右摇杆 Y |
| 4 bit0..5 | 本机六键 |
| 4 bit6 | 左肩键 |
| 4 bit7 | 右肩键 |
| 5 bit0 | `PE0` 拨动开关，1 为闭合 |
| 5 bit1..7 | 保留，固定为 `0` |

摇杆居中、按键和 PE0 均松开的本机测试数据为：

```text
80 80 80 80 00 00
```

仅将 PE0 闭合后，最后一个 payload 字节变为 `01`：

```text
80 80 80 80 00 01
```

摇杆输出范围为 `0..255`，中心为 `128`。物理方向是左推/上推为小值，右推/下推为大值；第一主控解析后转换为底盘坐标：

- 右推：`+vx`，车向右移动。
- 左推：`-vx`，车向左移动。
- 上推：`+vy`，车向前移动。
- 下推：`-vy`，车向后移动。

左摇杆最大平移速度为 `0.150 m/s`。只有左摇杆 X、Y 都回到 `128` 后，右摇杆才生效，右摇杆最大平移速度为 `0.075 m/s`。斜向输入会做矢量限幅。

左肩键输出 `+0.010 rad/s`，车逆时针旋转；右肩键输出 `-0.010 rad/s`，车顺时针旋转；两肩键同时按下时旋转速度为零。收到过本机帧后连续 `200 ms` 没有合法帧，底盘执行停车。

## 8. 遥控输入处理

- 数字按键和开关连续稳定约 `10 ms` 后才更新。
- 肩键映射范围为 `0..1000`，按下阈值 `600`，释放阈值 `550`。
- 摇杆中心死区为 `128 +/- 10`，死区内统一输出 `128`。
- 上电蜂鸣器响三次；数字按键或开关状态变化响一次；摇杆和肩键变化不响。

摇杆 12 位 ADC 标定值：

| 轴 | 最小值 | 中心值 | 最大值 |
| --- | ---: | ---: | ---: |
| 左 Y | 10 | 2103 | 4080 |
| 左 X | 10 | 1960 | 4080 |
| 右 X | 10 | 2142 | 4080 |
| 右 Y | 10 | 1964 | 4080 |

肩键原始 ADC 的松开区间为 `2030..2070`，两端满行程标定值为 `675` 和 `3722`。

## 9. 联调步骤

1. 遥控器上电，确认蜂鸣器响三次。
2. 接收端观察 `remote_link_rx_bytes` 和 `remote_link_control_frames` 持续增加，`remote_link_forward_overflows` 应保持为零。
3. 在 USART2 下游确认每次收到 `A5 5A` 开头的完整 10 字节帧。
4. 第一主控解析帧内第 2 至第 7 字节，第二主控解析第 8、9 字节。
5. 逐个操作右侧六键和五个第二主控开关，核对第 5 节位号；再单独操作 PE0，确认它只出现在第一主控数据中。
6. 从第二主控发送一段任意测试字节，确认第一主控和接收板不修改内容，并从 LoRa 端收到完全相同的字节序列。
7. 关闭遥控器，确认两块主控均在设定超时后清除输入或停车。

本机可观察的通信变量：

| 变量 | 含义 |
| --- | --- |
| `remote_link_rx_bytes` | LoRa 串口累计接收字节数 |
| `remote_link_forward_errors` | 通过 USART2 向第二主控转发失败次数 |
| `remote_link_forward_overflows` | 透明转发环形缓冲区溢出次数，正常应为 `0` |
| `remote_link_forwarded_bytes` | USART2 已成功转发的累计字节数 |
| `remote_link_return_errors` | 从 USART2 向 LoRa 串口回传失败次数 |
| `remote_link_return_overflows` | 回传环形缓冲区溢出次数，正常应为 `0` |
| `remote_link_returned_bytes` | 已原样回传到 LoRa 串口的累计字节数 |
| `remote_link_aux_control_frames` | SPI1 收到并通过校验的辅助控制帧数 |
| `remote_link_aux_crc_errors` | 辅助控制帧校验失败次数 |
| `remote_link_aux_spi_errors` | SPI1 接收错误次数 |

发送端可观察 `remote_tx_frame_count`、`remote_tx_busy_skip_count` 和 `remote_tx_error_count`。发送端和接收端均没有自动配置状态变量。

### 9.1 辅助控制 SPI 接线

H723 上层主控使用 SPI3 主机，接收板使用 SPI1 从机，均为 8 位、MSB 先发、SPI Mode 0。板间没有 NSS 引脚，软件使用固定 8 字节帧。

| H723 拓展板 U2 | 接收板 H3 | 信号 |
| --- | --- | --- |
| U2.1 / PB3 | H3.2 / PA5 | SCK |
| U2.2 / PB4 | H3.3 / PA6 | MISO，可省略 |
| U2.3 / PB5 | H3.4 / PA7 | MOSI |
| U2.5 / GND | H3.1 / GND | 共地 |

两块板已经各自供电时不要连接 U2.4 的 3V3。拓展板网表中 U2.2 是 MISO、U2.3 是 MOSI，接线应以网表为准。

## 10. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 第二主控完全收不到数据 | 串口是否为 115200 baud、TX/RX 是否交叉、是否共地 |
| 第一、第二主控数据错位 | 检查是否按 `A5 5A` 同步并固定接收 10 字节 |
| 某次数据被丢弃 | 检查 LoRa 模块的空中速率、AUX 忙状态和 `remote_tx_busy_skip_count`；协议无重传，只能等待下一帧状态覆盖 |
| 按键位顺序不对 | 对照第 5 节 bit0..bit5，不要按 GPIO 编号重新排序 |
| LoRa 有数据但下游主控没有 | 检查 `remote_link_forward_errors`、`remote_link_forward_overflows` 和 USART2 |
| 遥控关闭后机构保持动作 | 第二主控未实现通信超时清零 |

USART1 的 VOFA JustFloat 输出仅用于遥控器本地 ADC 调试，不属于上述控制协议。
