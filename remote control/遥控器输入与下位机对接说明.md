# 遥控链路交接文档

## 1. 交接目标

遥控器通过 LoRa 同时服务两块主控。遥控器负责采集全部输入并按目标 ID 发帧；本机主控接收所有 LoRa 数据，只解析属于自己的输入，属于第二主控的帧通过 McuLink 原样转发。

第二主控的队友只需要完成三件事：

1. 将接收串口配置为 `115200 baud、8N1`。
2. 按本文协议解析目标 ID `0x02` 的固定 5 字节帧。
3. 对右侧六个按键和五个开关实现业务逻辑，并增加通信超时保护。

## 2. 当前链路

```text
遥控器 STM32F4
  USART6，115200 baud
          |
          v
      LoRa 透明传输
          |
          v
遥控接收 STM32F103
  USART3，115200 baud
          |
          v
  双向字节级透明转发，不解析 target_id 或 payload
  USART2，115200 baud
          |
          v
  下游主控按 target_id 选择并解析 ID 1 或 ID 2
          ^
          |
  第二主控回传数据经第一主控、接收板原样送回 LoRa
```

遥控器每 `25 ms` 发送一个独立帧，ID 1 与 ID 2 交替发送，因此每个 ID 的更新率约为 `20 Hz`。两个 ID 不会拼在同一次 UART 发送中。

接收端上电时会通过 AUX 自动读取、写入并校验 E32 配置 `C0 00 06 3C 06 44`。遥控发送端不改写模块配置，只把 M0/M1 拉低并等待 AUX 就绪，因此发送端 E32 需要预先配置为相同信道和 `115200、8N1`。

当前相关代码：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 遥控输入 | `user/RemoteInput.c` | ADC 采样、数字输入消抖、蜂鸣器 |
| 遥控发送 | `user/Remote.c` | 目标 ID 独立分包、定时交替、USART6 发送 |
| 第一主控链路 | `../user/com_link/lora_link.c` | 解析 ID 1、原样转发 ID 2，并将第二主控回传原样送往接收板 |
| LoRa 接收与转发 | `../remote receive/Core/Src/remote_link.c` | USART3 与 USART2 双向缓冲并透明转发，不解析遥控帧 |

## 3. 输入归属

| 输入 | 硬件引脚 | 使用方 |
| --- | --- | --- |
| 左侧六键 | `PA0、PC1、PC0、PA1、PA2、PA4` | 本机主控 |
| 左、右摇杆 | `PB0、PB1、PC2、PC3` | 本机主控 |
| 左、右肩键 | `PA6、PA7` | 本机主控 |
| 本机拨动开关 | `PE0` | 本机主控 |
| 右侧六键 | `PD13、PD12、PD11、PD8、PD9、PD10` | 第二主控 |
| 第二主控开关 | `PE4、PE3、PE1、PD6、PD5` | 第二主控 |

数字输入在协议中已经统一为：`0` 表示松开或断开，`1` 表示按下或闭合。接收方不需要关心 GPIO 的低电平有效关系。

## 4. 帧格式

```text
A5 5A | target_id | payload
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 帧头 | 2 字节 | 固定为 `A5 5A` |
| `target_id` | 1 字节 | 本机 `0x01`，第二主控 `0x02` |
| `payload` | 固定 | ID 1 为 6 字节，ID 2 为 2 字节 |

协议没有类型、长度、序号和 CRC。解析器看到 `target_id=0x01` 后固定接收 6 字节 payload，看到 `target_id=0x02` 后固定接收 2 字节 payload。

## 5. 第二主控接收内容

第二主控正常情况下只会收到第一主控原样转发的 5 字节帧：

```text
A5 5A 02 key_bits switch_bits
```

### `key_bits`

| 位 | 遥控引脚 | 状态 |
| --- | --- | --- |
| bit0 | `PD13` | 1 为按下 |
| bit1 | `PD12` | 1 为按下 |
| bit2 | `PD11` | 1 为按下 |
| bit3 | `PD8` | 1 为按下 |
| bit4 | `PD9` | 1 为按下 |
| bit5 | `PD10` | 1 为按下 |
| bit6..7 | 保留 | 忽略 |

### `switch_bits`

| 位 | 遥控引脚 | 状态 |
| --- | --- | --- |
| bit0 | `PE4` | 1 为闭合 |
| bit1 | `PE3` | 1 为闭合 |
| bit2 | `PE1` | 1 为闭合 |
| bit3 | 保留，固定为 `0` | 忽略 |
| bit4 | `PD6` | 1 为闭合 |
| bit5 | `PD5` | 1 为闭合 |
| bit6..7 | 保留 | 忽略 |

空闲状态的完整测试帧为：

```text
A5 5A 02 00 00
```

可先用此帧检查第二主控解析器。

## 6. 第二主控解析要求

串口是连续字节流，不能假设一次 DMA 或中断正好收到一帧。接收程序按以下顺序处理：

1. 在字节流中寻找连续帧头 `A5 5A`。
2. 收到 `target_id=0x02` 后继续收 2 字节，总帧长固定为 5 字节。
3. 收满后一次性更新按键和开关状态。
4. 建议连续 `200 ms` 没有完整帧时清除输入并停止对应机构。

当前协议没有校验、应答和重传。遥控输入是周期状态量，后续完整帧会覆盖旧状态。

## 7. 第一主控解析要求

本机帧长度为 9 字节，payload 固定 6 字节：

| payload 字节 | 内容 |
| --- | --- |
| 0 | 左摇杆 X |
| 1 | 左摇杆 Y |
| 2 | 右摇杆 X |
| 3 | 右摇杆 Y |
| 4 bit0..5 | 本机六键 |
| 4 bit6 | 左肩键 |
| 4 bit7 | 右肩键 |
| 5 bit0 | `PE0` 拨动开关，1 为闭合 |
| 5 bit1..7 | 保留，固定为 `0` |

摇杆居中、按键和 PE0 均松开的本机测试帧为：

```text
A5 5A 01 80 80 80 80 00 00
```

仅将 PE0 闭合后，最后一个 payload 字节变为 `01`：

```text
A5 5A 01 80 80 80 80 00 01
```

摇杆输出范围为 `0..255`，中心为 `128`。物理方向是左推/上推为小值，右推/下推为大值；第一主控解析后转换为底盘坐标：

- 右推：`+vx`，车向右移动。
- 左推：`-vx`，车向左移动。
- 上推：`+vy`，车向前移动。
- 下推：`-vy`，车向后移动。

左摇杆最大平移速度为 `0.150 m/s`。只有左摇杆 X、Y 都回到 `128` 后，右摇杆才生效，右摇杆最大平移速度为 `0.075 m/s`。斜向输入会做矢量限幅。

左肩键输出 `+0.010 rad/s`，车逆时针旋转；右肩键输出 `-0.010 rad/s`，车顺时针旋转；两肩键同时按下时旋转速度为零。收到过本机帧后连续 `200 ms` 没有合法帧，底盘执行停车。

## 8. 遥控输入处理

- 数字按键和开关连续稳定约 `10 ms` 后才更新。
- 肩键映射范围为 `0..1000`，按下阈值 `600`，释放阈值 `550`。
- 摇杆中心死区为 `128 +/- 10`，死区内统一输出 `128`。
- 上电蜂鸣器响三次；数字按键或开关状态变化响一次；摇杆和肩键变化不响。

摇杆 12 位 ADC 标定值：

| 轴 | 最小值 | 中心值 | 最大值 |
| --- | ---: | ---: | ---: |
| 左 Y | 10 | 2103 | 4080 |
| 左 X | 10 | 1960 | 4080 |
| 右 X | 10 | 2142 | 4080 |
| 右 Y | 10 | 1964 | 4080 |

肩键原始 ADC 的松开区间为 `2030..2070`，两端满行程标定值为 `675` 和 `3722`。

## 9. 联调步骤

1. 遥控器上电，确认蜂鸣器响三次。
2. 接收端观察 `remote_link_rx_bytes` 和 `remote_link_forwarded_bytes` 同步持续增加，`remote_link_forward_overflows` 应保持为零。
3. 在 USART2 下游确认能够交替收到 ID 1 的 9 字节帧和 ID 2 的 5 字节帧，且两帧来自两次独立发送。
4. 第一主控解析 ID 1，第二主控解析 ID 2；接收板不读取任何 payload 字段。
5. 逐个操作右侧六键和五个第二主控开关，核对第 5 节位号；再单独操作 PE0，确认它只出现在 ID 1 帧。
6. 从第二主控发送一段任意测试字节，确认第一主控和接收板不修改内容，并从 LoRa 端收到完全相同的字节序列。
7. 关闭遥控器，确认两块主控均在设定超时后清除输入或停车。

本机可观察的通信变量：

| 变量 | 含义 |
| --- | --- |
| `remote_link_rx_bytes` | LoRa 串口累计接收字节数 |
| `remote_link_forward_errors` | 通过 USART2 向第二主控转发失败次数 |
| `remote_link_forward_overflows` | 透明转发环形缓冲区溢出次数，正常应为 `0` |
| `remote_link_forwarded_bytes` | USART2 已成功转发的累计字节数 |
| `remote_link_return_errors` | 从 USART2 向 LoRa 串口回传失败次数 |
| `remote_link_return_overflows` | 回传环形缓冲区溢出次数，正常应为 `0` |
| `remote_link_returned_bytes` | 已原样回传到 LoRa 串口的累计字节数 |
| `remote_link_lora_config_status` | 接收端 E32 配置状态，`2` 表示就绪 |

发送端可观察 `remote_lora_config_status`、`remote_lora_config_attempts`、`remote_lora_config_readback[6]`、`remote_tx_frame_count`、`remote_tx_busy_skip_count`、`remote_tx_config_skip_count` 和 `remote_tx_error_count`。

## 10. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 第二主控完全收不到数据 | 串口是否为 115200 baud、TX/RX 是否交叉、是否共地 |
| 能收到但无法分帧 | 是否按 ID 1 固定 9 字节、ID 2 固定 5 字节处理 |
| 偶尔错位 | 是否按连续字节流查找帧头，而不是依赖单次 DMA 长度 |
| 按键位顺序不对 | 对照第 5 节 bit0..bit5，不要按 GPIO 编号重新排序 |
| LoRa 有数据但下游主控没有 | 检查 `remote_link_forward_errors`、`remote_link_forward_overflows` 和 USART2 |
| 遥控关闭后机构保持动作 | 第二主控未实现通信超时清零 |

USART1 的 VOFA JustFloat 输出仅用于遥控器本地 ADC 调试，不属于上述控制协议。
